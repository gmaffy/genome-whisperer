The shape of the system

One binary, a thin command layer, and domain packages that mostly orchestrate external tools rather than compute anything themselves.

main.go is ten lines; it hands straight to cmd/, which is 23 Cobra files that parse flags, check dependencies, and call exactly one domain function each. Almost no logic lives there — the command files are a wiring layer, and the interesting decisions all sit one level down.

PackageLinesResponsibility
variants4,055gVCF creation, joint genotyping, concatenation, hard filtering. The engine behind VariantCalling, CreateGvcfs and MergeGvcfs.
bsaseq3,361Bulk-segregant analysis: filtering, G-statistic and Δ-allele-frequency, simulated thresholds, sliding windows, charts.
alignmentdir2,926Directory-driven alignment: scan, plan, execute per sample. Interval scatter and the runtime budget live here.
alignment1,678The individual tool invocations — aligners, MarkDuplicates, BQSR, indexing, CRAM conversion.
annotation1,422SnpEff runs, EFF-column splitting, gene descriptions, PRG BLAST joins, custom database building.
genespace808QTL interval → per-gene table with a priority classification, written to Excel.
pangenome793Iterative unmapped-read assembly that grows a reference.
utils600Config loading, dependency checks, shell execution, validation, reference resolution, memory sizing.

The system is an orchestrator. Nearly every stage shells out to bwa-mem2, bowtie2, pbmm2, samtools, bcftools, gatk, snpEff, DeepVariant or GLnexus through utils.RunBashCmd. What the Go code owns is which commands run, in what order, how many at once, and what may be skipped — and that last question is most of the complexity.

Three front doors, one plan

Discovery is the only thing that differs between the input modes. Everything after it is shared code.

A run can be described three ways, and they converge immediately:

ModeGivenDiscovery
data-dir-d /mnt/v/DATA plus species and reference versionGlobs the standard tree for clean_reads or bams directories and derives sample names from the path.
configA YAML file read by utils.ReadConfigTakes the explicit ReadPairs, Bams or GVCFs lists.
inlinePaths on the command lineNone — the paths are the work list.

For variant calling all three normalise into a single variants.Options struct, and RunPipeline executes the same three stages regardless of which door was used. absRoots makes every root absolute up front, so the paths printed in logs and the paths handed to GATK never depend on the working directory.

Why this matters historically. The package comment on RunPipeline records that the data-dir path used to stop after gVCF creation and never merge at all, because the two modes had separate implementations. Collapsing them into one struct is what makes the modes behave identically.

The directory contract

In data-dir mode the on-disk layout is the interface between stages. Nothing is passed between commands but the tree.

<dataDir>/
└── <species>/                        onion, maxima, pepper …
    └── <group>/                     a year or project folder — 2019, 2024 …
        └── <sample>/                ON1708 — this is the sample name
            ├── clean_reads/            *_1.fq.gz  *_2.fq.gz    ← stage 1 input
            └── reference_genomes/
                └── <refVer>/         GCA_030765085.1_ASM3076508v1
                    ├── bams/           RGMD.cram, RGMD_bqsr.cram, recal tables, QC pdf
                    ├── gatk_gvcfs/     <sample>.<chrom>.g.vcf.gz
                    └── dv_gvcfs/       the DeepVariant equivalent

Two rules follow from this and explain several behaviours downstream. The sample name is positional — it is the directory two levels under the species, not anything read out of a file — so a misplaced directory silently becomes a differently-named sample. And a stage's output directory is derived from its input's location: GvcfPath walks up from the bams directory to place gVCFs as siblings of it. Reference versions therefore stay isolated from each other for free.

Outside data-dir mode the same artefacts are laid out under an explicit --out-dir, keyed by chromosome rather than by sample. GvcfPath is the single function that knows both conventions.

End-to-end data flow

Five stages from FASTQ to an annotated table, three of which one command runs together.

Stage 1 — Alignment

The most stateful stage: it inspects what already exists and computes a per-sample plan before running anything.

01AlignReads alignmentdir/dirAlign.go
In
Paired FASTQs in clean_reads/, or any alignment intermediate already present in bams/
Out
<sample>.RGMD.cram, and with --bqsr also <sample>.RGMD_bqsr.cram, both indexed, plus recalibration tables and a QC plot
Tools
bwa-mem2 / bwa / bowtie2 / pbmm2, samtools, GATK

The run begins by scanning every sample's bams directory. inspectSampleBamDir classifies files by suffix, and getAlignmentFileInfo both validates each one and looks for a readable index — reading the index rather than merely stat-ing it, because an index left truncated by an interrupted run is present and non-empty but useless.

That snapshot goes to buildPlan, a pure function returning the ordered list of steps still required. Nothing re-scans the filesystem afterwards; processSample walks the plan, threading each step's output path into the next.

What BQSR actually does --bqsr

With no known-sites VCF available, --bootstrap manufactures one: HaplotypeCaller over the sample, then SelectVariants to split SNPs from INDELs, VariantFiltration with the standard GATK hard-filter expressions, and SelectVariants --exclude-filtered to keep what passed. Those two filtered files become the known sites. Recalibration then runs twice — before and after ApplyBQSR — so AnalyzeCovariates can draw the before/after plot.

A failure to draw that plot is caught and stepped over. It runs through Rscript and fails on any host missing gsalib or gplots, which is not a reason to discard a recalibration that has already finished.

Interval scatter references ≥ 1 Gb

Above a gigabase, single-process HaplotypeCaller and BaseRecalibrator passes run for days, so useScatter switches to the implementations in scatter.go. writeShardIntervals splits the reference into roughly equal interval lists, cutting long contigs into sub-intervals rather than leaving them whole — one-shard-per-contig would leave most cores idle waiting for the biggest piece — and packing the small-scaffold tail together so it does not become thousands of one-contig jobs. Shards that already exist on disk and validate are reused, so an interrupted run resumes at the shard it died on.

Stage 2 — gVCF creation

The unit of work becomes a sample × sequence-group pair, and stays that way until the merge.

02CreateGvcfs variants/createGvcfs.go
In
Recalibrated CRAM/BAM per sample (or the RGMD one with --no-bqsr)
Out
<sample>.<chrom>.g.vcf.gz per sample per sequence group, grouped by chromosome for the merge
Tools
GATK HaplotypeCaller, or DeepVariant in Docker

getChromsAndContigs reads the reference .dict, sorts sequences by length descending, and treats the longest 21 as chromosomes while everything shorter becomes a single "contigs" bundle called as one unit. Mitochondrial and plastid sequences are promoted into the chromosome group regardless of length.

FindSampleAlignments then locates one usable alignment per sample. selectAlignments encodes the preference order — recalibrated over RGMD, long-read-tagged files for long-read samples — and a sample with two equally plausible candidates is reported as ambiguous rather than guessed at.

Before any calling starts, discoverValidGvcfs checks what already exists. It validates in parallel and reuses anything sound, which is what makes a re-run after a partial failure cheap.

Two callers, one shape. CreateGvcfGATK and CreateGvcfDV take the same arguments and return the same thing. DeepVariant runs in a container and needs a model type, which is inferred from the sample name when not given; GATK takes an interval list. Everything downstream treats their outputs identically, apart from the filter profile in stage 4.

Stage 3 — Joint genotyping

The pipeline's most memory-hungry stage, and the one that most carefully checks its own inputs before spending hours.

03MergeGvcfs variants/mergeGVCFs.go
In
gVCFs grouped by chromosome, plus the cohort size stage 2 discovered
Out
One joint VCF per chromosome group, concatenated into a single cohort VCF
Tools
GATK GenomicsDBImport + GenotypeGVCFs, or GLnexus; GATK MergeVcfs

A chromosome is only merged if every expected sample is present for it. ExpectedSamples is threaded down from stage 1 precisely so the merge can tell "this chromosome is missing samples" apart from "this sample is missing everywhere" — a distinction it cannot make by inspecting gVCF counts alone.

Sample identity is checked by reading the names out of the gVCF headers and comparing as sets, not as ordered lists, so a differently-ordered cohort is not mistaken for a different one.

Scratch space is deliberately local

LocalWorkDir defaults to $HOME/.genome-whisperer/merge-work and is explicitly not the data directory. GenomicsDB workspaces, the GLnexus database, sample maps and interval lists do heavy small-file random I/O, which NAS and NFS storage handle badly. A GenomicsDB workspace is also fingerprinted, so a resumed run can tell whether an existing workspace was built from the same gVCFs and intervals, and discards it when it was not.

Stage 4 — Hard filtering

The one stage that reads and writes variant records in Go rather than shelling out.

04FilterVcf variants/filter.go
In
The cohort VCF
Out
A filtered VCF; SNPs and INDELs judged by their own thresholds
Tools
None — vcfgo in-process

classifyVariant labels each record as SNP, INDEL or MNP, and the thresholds are then applied by whichever profile matches the caller. PassesHardFilter implements the GATK profile over QD, QUAL, SOR, FS, MQ, MQRankSum and ReadPosRankSum, read from a utils.HardFilterConfig so a project can override them from its config file.

passesDeepVariant exists because DeepVariant output carries none of those annotations. It judges on QUAL and genotype quality instead, and deliberately ignores missing GATK fields rather than treating absence as failure.

A zero-valued config is not a permissive one. There is a test named for this: an empty HardFilterConfig discards almost everything, because a threshold of zero is still a threshold. Configs should set the values they mean, not rely on omission.

Stage 5 — Annotation

Three joins that turn a VCF into something a breeder can read.

05CreateSuperVcf annotation/annotation.go
In
Filtered VCF, a SnpEff database, a gene-description table, a PRG BLAST table
Out
*_SUPER_VCF.tsv — one row per variant with effect, gene description and protein-hit statistics
Tools
SnpEff, GATK VariantsToTable

SnpEff annotates, then splitEffColumns unpacks the packed EFF field into real columns. Gene descriptions and PRG BLAST hits are then joined on gene or transcript identifier.

Which identifier to join on is detected, not assumed. The code counts how many gene names and how many transcript IDs from the variant table actually appear in each lookup file, and picks the column that overlaps. When neither overlaps it stops and says so, rather than emitting a table where every annotation column reads NA — the failure mode that motivated the check.

CreateSnpEffDB builds the custom database this stage needs, from a reference FASTA, protein FASTA, CDS FASTA and GFF3.

How resume works

Every long stage can be re-run, and the mechanism is the same idea applied at four scales.

The governing rule is that the filesystem is the source of truth, and existence is not enough. An artefact counts as done when it is present, non-empty, passes a validity check, and carries a readable index where one is expected. That last clause exists because an interrupted samtools index leaves a file that looks finished to a directory scan.

ScaleUnitDecided by
sampleWhole alignment planbuildPlan from the scanned state — the plan simply starts later
shardOne interval of a scattered GATK stepShard output present and valid → skipped, and the count reported
gVCFSample × chromosomediscoverValidGvcfs, validating in parallel
mergeGenomicsDB workspacegdbFingerprint over the gVCF list and intervals

There is also an older journal mechanism — utils.ParseLogFile and StageHasCompleted read a structured log and ask whether a named program finished for a given sample and chromosome. The pangenome loop and the v1 BQSR path still use it. The newer directory-driven code deliberately does not, on the grounds that a journal can disagree with the disk and the disk is what the next tool will actually read.

Validation has two speeds. --quick checks structure — samtools quickcheck, an index's presence, a BGZF integrity test. Without it, files are decoded end to end. Quick is right for a re-run over known-good data and wrong for verifying a transfer, and the difference is not cosmetic: quickcheck never inspects contig names, so it will pass a CRAM that no tool in the pipeline can actually decode.

Concurrency and memory

Parallelism is multiplicative here, which is why it is budgeted centrally rather than per call site.

Five samples each scattering a HaplotypeCaller across twenty intervals is a hundred JVMs, and each costs a few gigabytes. Two mechanisms keep that bounded.

runtimeOpts is computed once per run and carries the per-sample thread budget, the JVM heap options for whole-sample steps, a smaller heap for shard steps, the shard count and the pair-HMM thread count. Every external command is sized from those figures, so no call site guesses.

gatkSlots is a package-level semaphore bounding how many GATK JVMs exist at once across the whole process. The subtlety is recorded in its comment: only leaf commands take a slot. A function that spawns shards must not hold one itself, or the shards it is waiting on can never acquire theirs — a self-deadlock that would look like a hang.

The merge stage budgets differently again. mergeJobs reads MemAvailable from /proc/meminfo and decides both how many chromosome groups run at once and how large each job's heaps may be, because merging is memory-bound rather than CPU-bound. Raising the job count shrinks the heaps rather than oversubscribing the machine.

When not run verbosely, runGatk captures output rather than discarding it and replays the last 25 lines on failure. A scattered step that dies otherwise reports nothing but an exit status, once per shard, which is no use hours into a run.

The downstream branches

Three analyses hang off the main pipeline, plus one that grows a reference instead of consuming one.

GoBSAseq bsaseq

Bulk-segregant analysis, and the only branch that can drive the whole pipeline itself — given a config it will align, call variants through RunPipeline, and then analyse. The VCF becomes a per-variant TSV of parent and bulk depths, which is filtered by minimum depth, reduced to per-variant statistics (Δ allele frequency and a G-statistic), and smoothed over sliding windows.

Significance thresholds are simulated rather than assumed: simulateAF draws allele frequencies for the given bulk sizes and population structure over many replicates, and the resulting quantiles become the threshold curves plotted alongside the data. Peak and valley detection then reports where the smoothed statistic crosses those curves. Output is an interactive go-echarts HTML chart plus the underlying CSV.

Three designs are supported — two bulks with two parents, two bulks alone, and one bulk with two parents — each with its own reader, filter and statistics path.

GeneSpace genespace

Takes a QTL interval and turns it into a candidate-gene shortlist. It reads gene positions from the GFF, variant records for the interval, gene descriptions and PRG BLAST hits, then keeps genes where the resistant lines differ from the susceptible ones. ClassifyPriority ranks what survives, and the result is written as Excel.

GoPan pangenome

The one loop that modifies its own input. For each sample in turn: align to the current reference, extract the unmapped reads, assemble them with MEGAHIT or MaSuRCA, trim and rename the resulting scaffolds so they carry the sample name, and concatenate them onto the reference. The next sample aligns against that larger reference. LatestRef finds the highest-numbered reference produced so far, which is what lets an interrupted run pick up mid-cohort.

Sharp edges

Things that are true of the code today and worth knowing before you change it.

The 21-sequence split is a heuristic

getChromsAndContigs calls the longest 21 sequences "chromosomes" and bundles the rest. For a chromosome-scale assembly that is right. For a fragmented one it is arbitrary — on a reference with 2,099 sequences the cut lands wherever the length distribution happens to put it, and the bundle can be very large. Nothing validates that the split matches the biology.

Index ceilings on large genomes

BAI, TBI and the index htsjdk builds from a CRAI all stop at 536,870,911 bp. Onion and pepper references exceed that, which changes which file formats the pipeline may use for reads and for variants. refExceedsBaiLimit is the predicate that decides; the reasoning is written up separately in The 512 Mb Ceiling.

variants/createGvcfs.go still hardcodes .g.vcf.gz, so CreateGvcfs has not yet been adapted for those references.

Two generations of code coexist

old/ holds the v1 and v2 implementations, and variants/REDESIGN.md documents the duplication that motivated the current package — two implementations of the same biology with different layouts, resume strategies and concurrency models, only one of which reached a merged VCF. That plan describes a further refactor: a single Layout owning every path, a Runner interface making external tools injectable, and a pure core with a thin shell. Worth reading before extending variants, since it lists the specific bugs the structure is meant to prevent.

Error handling is uneven

variants, annotation, genespace and utils return errors properly and let the caller decide. The older packages do not: there are 57 log.Fatal calls outside cmd/ — 31 in bsaseq, 15 in alignment, 7 in alignmentdir, 4 in pangenome — each of which kills the process from inside a library function, so a single bad sample can end a whole cohort run and none of those paths can be unit-tested. The annotation package also returns (error, T) rather than the conventional (T, error).
